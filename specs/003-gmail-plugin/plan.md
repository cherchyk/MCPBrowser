# Implementation Plan: Gmail Plugin (Hybrid UI Resilience)

**Branch**: `003-gmail-plugin` | **Date**: 2026-04-03 (rewrite) | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/003-gmail-plugin/spec.md`

## Summary

Build a Gmail site-specific plugin for MCPBrowser that automates 11 email management actions (list, read, search, compose, reply, forward, archive, delete, label, mark-read, mark-unread). The plugin uses a **tiered interaction strategy** (FR-011) to maximize resilience against Gmail UI changes: URL hash navigation (Tier 1) for navigation, keyboard shortcuts (Tier 2) for actions, ARIA/data-*/semantic HTML (Tier 3) for data extraction and form filling, and CSS class selectors (Tier 4) only as a last resort for email row internals. The plugin implements the MCPBrowser plugin interface (interfaceVersion 1) from feature 002-site-plugins.

## Technical Context

**Language/Version**: JavaScript (ES modules), Node.js 18+  
**Primary Dependencies**: Puppeteer-core (for `page.keyboard`, `page.$()`, `page.evaluate()`), MCPBrowser core (responses.js, plugin-loader.js, browser.js, logger.js)  
**Storage**: N/A (stateless plugin, no persistence)  
**Testing**: Node.js built-in test runner (`node --test`), fixture-based HTML for unit tests, real Gmail for browser integration  
**Target Platform**: MCPBrowser MCP server running on user's machine  
**Project Type**: Plugin module within the MCPBrowser npm package  
**Performance Goals**: <5 seconds per action on standard connection (SC-001)  
**Constraints**: Stateless between calls (FR-017), 10s content timeout (FR-012), ≥70% Tier 1/2 coverage (SC-007)  
**Scale/Scope**: 11 actions, ~15 source files, ~15 test files
